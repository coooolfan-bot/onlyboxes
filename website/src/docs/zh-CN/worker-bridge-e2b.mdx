# E2B 桥接运行时

`worker-bridge-e2b` 将 Onlyboxes 桥接到 [e2b](https://e2b.dev/) 云沙箱平台。它通过 gRPC 连接控制节点，将 e2b 沙箱暴露为标准 worker，支持 echo、pythonExec 和 terminalExec。

## 适用场景

- 希望使用基于云的沙箱而无需管理基础设施
- 需要快速扩展而不受本地资源限制
- 偏好按使用付费模式而非自托管计算
- 已配置好 e2b 模板

## 工作原理

1. Worker 通过 gRPC 连接控制节点。
2. 对于 `pythonExec`，它创建新的 e2b 沙箱，将代码写入 `/tmp/code.py`，通过 `uv run /tmp/code.py` 执行（支持 PEP 723 内联依赖），然后销毁沙箱。
3. 对于 `terminalExec`，它创建基于租约 TTL 的持久化 e2b 沙箱会话。相同 `session_id` 的后续命令会复用会话，空闲时自动清理。
4. 输出通过控制面流式返回。

## 前置条件

- 具有 API key 的 e2b 账号
- 为 Python 和终端执行预配置的 e2b 模板
- 能够访问控制节点 gRPC 端口

### 模板要求

**Python 执行模板** (`E2B_PYTHON_EXEC_TEMPLATE`):
- 必须预装 `uv`（推荐基础镜像：`ghcr.io/astral-sh/uv:python3.12-bookworm-slim`）

**终端执行模板** (`E2B_TERMINAL_EXEC_TEMPLATE`):
- 应包含终端会话所需的通用工具
- 可以是包含预装软件包的自定义模板

## 启动 worker

`worker-bridge-e2b` 使用 Python 实现，需要 `uv` 进行依赖管理。克隆仓库并设置 worker：

```bash
cd worker/worker-bridge-e2b
uv sync
bash scripts/gen_proto.sh  # 如需要可重新生成 protobuf stubs
```

然后启动 worker：

```bash
WORKER_CONSOLE_GRPC_TARGET=127.0.0.1:50051 \
WORKER_CONSOLE_INSECURE=true \
WORKER_ID=<worker_id> \
WORKER_SECRET=<worker_secret> \
E2B_API_KEY=<e2b_api_key> \
E2B_PYTHON_EXEC_TEMPLATE=<template_for_python> \
E2B_TERMINAL_EXEC_TEMPLATE=<template_for_terminal> \
uv run worker-bridge-e2b
```

通过非 TLS 连接时请设置 `WORKER_CONSOLE_INSECURE=true`。

## 环境变量

### 必填

| 变量 | 说明 |
| --- | --- |
| `WORKER_ID` | Dashboard 中的 Worker 节点 ID |
| `WORKER_SECRET` | 创建 worker 时的一次性密钥 |
| `E2B_API_KEY` | 你的 e2b API 密钥 |

### 连接

| 变量 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `WORKER_CONSOLE_GRPC_TARGET` | 否 | `127.0.0.1:50051` | 控制节点 gRPC 地址 |
| `WORKER_CONSOLE_INSECURE` | 否 | `false` | 设为 `true` 允许不安全的连接（非 TLS） |

### 身份

| 变量 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `WORKER_NODE_NAME` | 否 | | 可读的节点名称 |
| `WORKER_VERSION` | 否 | `dev` | 上报给控制节点的版本号 |
| `WORKER_LABELS` | 否 | | CSV 格式标签，如 `region=us,cloud=e2b` |

### E2B 沙箱

| 变量 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `E2B_PYTHON_EXEC_TEMPLATE` | 否 | `base` | pythonExec 沙箱模板 |
| `E2B_TERMINAL_EXEC_TEMPLATE` | 否 | `base` | terminalExec 沙箱模板 |
| `E2B_SANDBOX_TIMEOUT_SEC` | 否 | `300` | 沙箱生命周期（秒） |

### 并发上限

| 变量 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `WORKER_ECHO_MAX_INFLIGHT` | 否 | `4` | echo 最大并发数 |
| `WORKER_PYTHON_EXEC_MAX_INFLIGHT` | 否 | `4` | pythonExec 最大并发数 |
| `WORKER_TERMINAL_EXEC_MAX_INFLIGHT` | 否 | `4` | terminalExec 最大并发数 |

### 终端会话租约

| 变量 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `WORKER_TERMINAL_LEASE_MIN_SEC` | 否 | `60` | 最短租约时长（秒） |
| `WORKER_TERMINAL_LEASE_MAX_SEC` | 否 | `1800` | 最长租约时长（秒） |
| `WORKER_TERMINAL_LEASE_DEFAULT_SEC` | 否 | `60` | 默认租约时长（秒） |
| `WORKER_TERMINAL_OUTPUT_LIMIT_BYTES` | 否 | `1048576` | 每个流的输出上限（字节） |

### 心跳

| 变量 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `WORKER_HEARTBEAT_INTERVAL_SEC` | 否 | `5` | 心跳间隔（秒） |
| `WORKER_HEARTBEAT_JITTER_PCT` | 否 | `20` | 抖动百分比（0–100） |

### 日志

| 变量 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `WORKER_LOG_LEVEL` | 否 | `info` | `debug` / `info` / `warn` / `error` |
| `WORKER_LOG_FORMAT` | 否 | `json` | `json` / `text` |

## 成本考量

与自托管 worker 不同，e2b 根据沙箱使用情况收费。监控你的 e2b dashboard 以追踪成本。考虑：

- 短期 `pythonExec` 沙箱在每次执行时创建和销毁
- 长期运行的 `terminalExec` 会话持续到租约过期
- 调整租约超时以平衡会话复用与空闲成本
